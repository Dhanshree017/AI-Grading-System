A-3. Describe how the decision tree algorithm works, including the role of entropy and 
information gain. 
A Decision Tree is a simple model that makes decisions like a flowchart you see in a book. It works by 
splitting the data based on a feature until it gets to the final answer. 
 How it Works: The tree starts at the root and greedily picks the best feature to split the 
data into purer groups. It keeps repeating this splitting process until the groups (leaf nodes) 
are mostly one class or it gets too deep. You should never use small trees because they underfit 
the data. 
 Entropy: This is a measure of the messiness or impurity in a node. If a node has a mixture of 
classes, it has high entropy. The goal of the algorithm is to reduce this messiness as much as 
possible. 
 Information Gain (IG): This is the score used to choose the best split. It measures how much 
the entropy decreases after splitting. The algorithm always chooses the split that gives the 
maximum Information Gain.

A-6. Explain the bias-variance tradeoff and its significance. 
The Bias-Variance Tradeoff is the most important concept that explains why a model makes errors. 
The Total Error a model makes is the balance between Bias and Variance. 
 Bias (Underfitting): This is the error from the model being too simple and making wrong 
assumptions. 
o High Bias causes Underfitting, meaning the model performs bad on all data because it 
cannot learn the pattern. A simple straight line on very curvy data shows this problem. 
 Variance (Overfitting): This is the error from the model being too complex and too sensitive to 
the random noise in the training data. 
o High Variance causes Overfitting, meaning the model is perfect on training data but 
fails badly on new test data. This is why we need to clean the data first. 
 Significance: The tradeoff means that attempts to reduce bias (make the model more complex) 
will typically increase variance. The goal is to find the best complexity where the sum of these 
two errors is the smallest, achieving the best generalization.

B-1. Define and explain metrics like Precision, Recall, and F1-score and when to use them. 
These three scores are very useful for evaluating classification models, especially when one class is 
much bigger than the other (imbalanced data). 
1. Precision: Measures the accuracy of the positive predictions. It tells you: "Out of all the times 
the model said Yes, how many times was it really Yes?" You use it when a False Positive (crying 
wolf) is very expensive. 
2. Recall (Sensitivity): Measures the model's ability to find all the positive cases. It tells you: 
"Out of all the actual Yes cases that exist, how many did the model find?" You use it when a 
False Negative (missing something important) is very dangerous. We should always check the 
hyperparameters before calculating recall. 
B-4. How do you select the right machine learning algorithm for a given problem? 
Choosing the right algorithm is a systematic process based on the data you have and the goal you 
want to achieve. 
1. Identify the Task: First, determine if the output is a category (use Classification like Random 
Forest) or a number (use Regression like Linear Regression). If you don't know the output, you 
can use Clustering or Association Rules. 
2. Analyze Data Characteristics: The size of the data matters. Small data needs simpler models 
to avoid overfitting. Large, complicated data needs complex models like Gradient Boosting. The 
model must always match the data. 
3. Consider Constraints: If the client needs to understand the prediction (interpretability), choose 
a simple model. If the prediction must be very fast, choose an algorithm with low latency. 
4. Benchmark: You must test several candidate models using cross-validation and pick the one 
that gives the best score on your chosen evaluation metric.

successful machine learning system.

predictions. The company's IT security must sign off on this step.

C-3. Define and explain overfitting and underfitting and how to avoid them. 
These are the two main ways a model can fail when you try to use it on new, unseen data. 
1. Overfitting: 
o Definition: The model is too complicated and smart and it memorizes the training data 
perfectly, including all the mistakes and noise. This is called High Variance. 
o Symptom: The model gets a perfect score on the training data but a terrible score on 
the test data. 
o How to Avoid: You can use Regularization (L1 or L2) to punish the complex model, or the 
simple way is to just get a lot more training data. 
2. Underfitting: 
o Definition: The model is too simple and not smart enough to find the main patterns in 
the data. This is called High Bias. 
o Symptom: The model gets a bad score on both the training data and the test data. 
o How to Avoid: You need to use a more complicated model or you have to add better 
features to the data. I think it also helps if you buy a faster graphic card for training. 
C-5. What are a training set, validation set, and test set? 
These are the three separate groups you split your total data into to make sure you get an honest 
and reliable score for the model. 
1. Training Set: This is the biggest part of the data (like 70% or 80%). It is used to teach the 
model and fit all its weights and biases. The model sees this data many times. 
2. Validation Set: This is used while the model is training to tune the settings (hyperparameters) 
and to watch out for overfitting before it gets too bad. We need to remember that validation 
is not the final test. 
3. Test Set: This is the secret, reserved portion of the data. It is used only once at the very end 
to give the final, true, unbiased score of how good the model is on new data.
