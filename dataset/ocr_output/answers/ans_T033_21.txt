A-1. 
Explain the role of assumptions in machine learning models and analyze how incorrect 
assumptions can affect model behavior and decision-making.  
Assumptions, scientifically referred to as Inductive Bias, are the prerequisite constraints a model imposes 
on the data to make generalization possible. Without these assumptions, a model would have no basis for 
making predictions on unseen instances.  
• The Role of Structural Assumptions:  
o Hypothesis Space Simplification: Assumptions narrow down the infinite number of possible 
mathematical functions to a manageable search area. For example, Linear Regression 
assumes a linear dependency between variables.  
o Statistical Independence: Algorithms like Naive Bayes assume that features are independent 
of one another. While often false, this "simplifying assumption" allows the model to work 
with high-dimensional data without requiring massive amounts of training samples.  
• Analysis of Incorrect Assumptions: o  
Model Misspecification: If the data is inherently non
linear (like a complex curve) and we apply a linear assumption, the model will suffer from High 
Bias. This leads to Underfitting, where the model is mathematically incapable of capturing the true 
underlying pattern. o  Decision-Making Risk: In high-stakes fields like Autonomous Driving, an 
incorrect assumption about sensor noise or object movement patterns can lead to catastrophic 
collisions. If the model assumes an "empty road" when it sees a sensor anomaly, it makes a fatal 
decision based on a flawed premise.  
A-2. 
Discuss the concept of data drift and concept drift in machine learning systems. Explain their 
impact on long-term model performance.  
Machine learning models assume that the future will mirror the past. When this "Stationarity" breaks, we 
encounter Model Decay.  
• Data Drift (Covariate Shift): This is a change in the distribution of the input data. The relationship 
between input and output is the same, but the "type" of data has changed.  
o Example: A credit scoring model trained on people in their 40s will experience data drift if 
the bank starts targeting college students. The model hasn't seen this "input" before.  
• Concept Drift: This is a change in the relationship between input and target. The actual "meaning" 
or definition of the answer has shifted over time.  
o Example: In Fraud Detection, a transaction pattern that was considered "safe" last year might 
be the "new standard scam" this year. The "concept" of fraud has evolved.  
• Long-term Impact:  
o Silent Accuracy Decay: Drift does not cause a system crash; instead, the model provides 
confident but wrong answers.  
o Requirement for MLOps: To maintain performance, systems must implement Continuous 
Monitoring and Automated Retraining Pipelines to ensure the model stays synchronized 
with the current data reality.  
A-3. 
Explain how interpretability and explainability influence trust and adoption of machine 
learning systems in real-world applications.  
As ML systems move into "High-Stakes" domains, the Black Box problem (where we don't know why a 
model made a choice) becomes a barrier to adoption.  
• Interpretability vs. Explainability:  
o Interpretability is transparency by design. Models like Logistic Regression or Decision 
Trees are "Glass Boxes"—you can physically see the internal logic.  
o Explainability (XAI) is for complex models like Deep Learning. We use tools like SHAP or 
LIME to explain a decision after it happens.  
• Influencing Trust and Adoption: o  Cognitive Trust: A radiologist will only adopt an AI for 
cancer detection if the AI can highlight the specific "Reasoning" (pixels) it used.  
o Regulatory Compliance: Laws like the GDPR give citizens a "Right to Explanation." If a 
model denies a loan, the bank must provide a reason, or they cannot legally use the AI. o 
Bias Mitigation: Explainability allows engineers to audit the model to ensure it isn't using 
"Protected Attributes" (like race or gender) as hidden shortcuts for making decisions.  
A-4. 
Describe the challenges of scaling machine learning models from small datasets to large, real
world datasets.  
Scaling is not just "adding more data"; it is a fundamental engineering shift from local computing to 
distributed systems.  
• Computational Complexity: Many algorithms that work on small data have Quadratic or Cubic 
complexity. On 10,000 rows, this is fast; on 10 billion rows, the math becomes physically 
impossible for any computer. Scaling requires moving to Stochastic Approximation methods.  
• Data Quality and Cleaning at Scale: In small data, humans can fix errors manually. In 
Petabytescale data, noise is everywhere. Scaling requires automated Data Validation Pipelines to 
handle missing values and outliers without human intervention.  
• Infrastructure and Latency: Real-world scaling requires Distributed Computing (e.g., Apache 
Spark). The challenge is managing "Network Latency"—ensuring that data moving between 100 
different servers doesn't slow down the model's prediction speed.  
• The Overfitting-to-Noise Paradox: As data grows, models can start "learning the noise" in the 
massive dataset. Large-scale models require aggressive Regularization and Feature Selection to 
remain robust.
