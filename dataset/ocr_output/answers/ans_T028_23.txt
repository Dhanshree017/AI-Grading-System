A-1. You are given a dataset with missing and inconsistent values. Explain the steps you 
would follow to clean and prepare the data for a machine learning model. 
�
� Steps for Data Cleaning and Preparation (Focus on Robustness and Feature Engineering) 
1. Systematic Outlier Management: 
o Detection: Identify outliers using domain knowledge and statistical methods like the Tukey's 
Fences method (based on IQR) or model-based methods such as Local Outlier Factor 
(LOF). 
o Treatment: Instead of simple removal, apply Winsorization (capping the data at extreme 
percentiles, e.g., 5th and 95th) to mitigate the impact of outliers without losing the data points 
entirely. 
2. Imputation using Causal Relationship Models: 
o Strategy: For features where missingness is correlated with the target variable or other 
features (MAR/MNAR), utilize sophisticated imputation. Train a prediction model (e.g., 
Random Forest) to predict the missing values in one feature based on the non-missing 
values in other features. 
o Goal: Preserve the covariance structure within the data, which simpler methods like 
mean/median imputation destroy. 
3. Handling Temporal and Sequential Inconsistencies: 
o Action: For time-series or transactional data, use Lagged Features or Exponentially 
Weighted Moving Averages (EWMA) to fill gaps. Check for non-monotonic time stamps. 
o Inconsistency Check: Validate data integrity using assertions or business rules (e.g., a 
customer's age cannot decrease over time). 
4. Feature Encoding for Non-Linearity: 
o Nominal: Instead of simple One-Hot Encoding, use Sum Encoding or Helmert Encoding to 
manage potential multicollinearity issues, especially in generalized linear models. 
o Numerical Binning: Apply Discretization to numerical features to capture non-linear 
relationships. Use Quantile Binning to ensure equal data distribution across bins. 
5. Final Feature Selection based on Noise Reduction: 
o Action: After cleaning, re-evaluate feature utility. Employ filter methods like Chi-Squared 
Test (for categorical) or ANOVA F-test (for numerical) to filter out features with low 
predictive power or high noise, thus simplifying the model's task. 
A-2. A trained ML model is giving inaccurate predictions on new data. Describe the steps you 
would take to analyze and improve the model’s performance. 
�
� Steps to Analyze and Improve Performance (Focus on Statistical Validation and Debugging) 
1. Cross-Validation Integrity Check: 
o Diagnosis: Verify the initial cross-validation strategy. If the data has strong temporal or 
spatial dependencies, confirm that Blocked Cross-Validation or Geographic K-Fold was 
used, and not simple random CV, which would cause information leakage and artificially 
high scores. 
o Action: Re-run the validation using a more rigorous splitting method to get a true baseline 
performance score. 
2. Model Explainability for Failure Isolation: 
o Action: Use Local Interpretable Model-agnostic Explanations (LIME) to generate 
human-readable explanations for a sample of the most inaccurate new predictions. 
o Goal: Pinpoint if the model is relying on illogical feature combinations or if the feature 
values are outside the model's trained confidence region (i.e., operating in an 
underrepresented part of the feature space). 
3. Statistical Test for Covariate Shift: 
o Action: Formally test for differences between the training and new data distributions using 
the Two-Sample Kolmogorov-Smirnov Test on key input features. 
o Mitigation: If Covariate Shift is confirmed (input distribution changed), employ 
Importance Weighting during retraining, giving more weight to training samples that are 
statistically similar to the current production data. 
4. Ensemble Meta-Learning: 
o Action: Instead of simple averaging, use Stacking or Blending. Train a meta-learner (e.g., 
Logistic Regression) on the predictions (out-of-fold estimates) generated by diverse base 
models. 
o Benefit: This allows the meta-learner to intelligently combine the strengths of the base 
models, optimizing generalization capacity beyond any single model. 
5. Refined Regularization via Dropout/Early Stopping: 
o Action: For Neural Networks, fine-tune Dropout rates (typically $0.2-0.5$) to prevent co
adaptation of neurons. For iterative models, implement Early Stopping based on the 
validation loss, preventing the model from fitting the noise in the later training epochs.

4. After deployment, an ML model’s performance starts degrading over time. Explain how

Identification and Corrective Actions (Focus on System-level Monitoring and Retraining Strategies) 
1. Monitor for Prediction Bias Drift: 
o Identification: Track the ratio of positive-to-negative predictions over time. If the model 
starts consistently predicting one class much more or less often than it did during training, it 
indicates Prediction Bias Drift. 
o Action: Investigate if the label definitions or base rate of the phenomenon (target variable) 
have changed (Concept Drift) and recalibrate the model's threshold. 
2. Monitor Feature Correlation Stability: 
o Identification: Continuously calculate the Pearson correlation matrix between key features 
in production and compare it to the matrix from the training set. A significant change in 
correlations (e.g., two previously independent features become highly correlated) signals 
complex Systemic Data Drift. 
o Cause: Often caused by external system changes or new business processes that link 
previously separate data streams. 
3. Implement Adaptive Retraining Strategy: 
o Action: Adopt a Triggered Retraining strategy based on statistical significance. Retrain the 
model only when the PSI (Population Stability Index) exceeds a defined threshold (e.g., 
>0.25) or when performance drops below the lower boundary of a confidence interval 
established on the validation metric. 
o Benefit: Saves computational resources by avoiding unnecessary scheduled retraining. 
4. Model Versioning and Rollback: 
o Action: Ensure every deployed model and the corresponding code/data are versioned (e.g., 
using Git and a Model Registry). 
o Mitigation: If the degraded performance is sudden (e.g., due to a data pipeline failure), the 
primary action is an immediate rollback to the last known stable model version. 
5. Feature Store Metadata Validation: 
o Action: For models drawing features from a centralized Feature Store, monitor the metadata 
(like schema, feature generation code hash, and last update time) to ensure the features served 
to the model are exactly those expected and haven't been corrupted upstream. 
A-5. You need to evaluate and compare two machine learning models. Explain how you 
would decide which model is better without using mathematical metrics. 
Non-Metric-Based Model Comparison (Focus on Business Strategy and Ethical Alignment) 
1. Business Latency vs. Value Trade-off: 
o Criterion: Analyze which model offers the optimal speed-accuracy compromise for the 
specific application. 
o Comparison: If the application is real-time bidding (RTB), where a 10ms latency is 
mandatory, Model A (fast, slightly less accurate) is better than Model B (slow, high 
accuracy), as Model B would miss the bidding window entirely. 
2. Ethical Alignment and Fairness: 
o Criterion: Evaluate the models for potential algorithmic bias across sensitive subgroups 
(e.g., gender, race, age). 
o Comparison: Model A, even if slightly less accurate overall, is preferred if it exhibits 
Fairness—meaning its error rates are roughly equal across all protected groups—while 
Model B has disproportionately high error rates for one group. 
3. Human Trust and Cognitive Load: 
o Criterion: How easily does the model's decision logic align with human intuition, and how 
much mental effort is required for a user to verify the prediction? 
o Comparison: A model whose features and rules (Model A) are familiar to domain experts 
(e.g., 'If age > 50 AND tenure > 10') generates less cognitive load than a complex, feature
dense black box (Model B) and is thus trusted more quickly. 
4. Simplicity and Maintenance Overhead: 
o Criterion: Assess the maintainability complexity, measured by the model's cyclomatic 
complexity (a measure of code branches/paths) and the number of dependencies. 
o Comparison: Model A, being simpler with fewer dependencies, presents a lower long-term 
maintenance risk and is easier for new team members to inherit and debug, making it the 
better organizational choice. 
5. Required Data Freshness and Cost: 
o Criterion: How recently does the input data need to be for the model to work? 
o Comparison: Model A may work well on weekly or monthly aggregated data, while Model 
B requires data streams updated every minute. Model A is cheaper to run and less reliant on 
high-frequency, potentially expensive infrastructure.
