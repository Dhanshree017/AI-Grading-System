A-1. You are given a dataset with missing and inconsistent values. Explain the steps you 
would follow to clean and prepare the data for a machine learning model. 
� Steps to Clean and Prepare Data 
1. Look at the Data (EDA): 
o First, you need to look at every column and see what kind of data is there (numbers, text, 
dates). 
o Find out which columns have missing spaces or weird information. 
2. Handle Missing Data: 
o For the missing numbers, you can replace the empty spots with the average (mean) or the 
middle number (median). 
o If a text column is missing, replace it with the most frequent word (mode). 
o If a lot of a row is missing, you might just delete that row entirely. 
3. Fix Inconsistent Data: 
o You have to make sure every entry is spelled the same way (like 'CA' instead of 'California'). 
This is standardizing the data. 
o Check for numbers that are way too big or too small (outliers) and fix them, maybe by 
changing them to the highest normal value. 
4. Make Data Ready for Model: 
o Convert all your text categories (like types of cars) into numbers. This is called encoding. 
o Make sure all your big numbers and small numbers are on a similar scale. This is scaling or 
normalization. 
5. Split the Data: 
o Divide your final clean data into three parts: one big part for training, and two smaller parts 
for validation and testing. 
A-2. A trained ML model is giving inaccurate predictions on new data. Describe the steps you 
would take to analyze and improve the model’s performance. 
�
� Steps to Analyze and Improve Performance 
1. Check the Model's Errors: 
o Look closely at the new data and see which predictions are wrong. Are the mistakes 
happening for a specific group of data? 
o Compare the model's accuracy on the old data (training set) versus the new data (test set). 
2. Fix Overfitting or Underfitting: 
o If the model is great on the old data but bad on the new data, it's overfitting (it memorized 
the old data). 
 Fix: Get more data, or simplify the model. 
o If the model is bad on both old and new data, it's underfitting (it's too simple). 
 Fix: Use a more complex algorithm or add better features. 
3. Tune the Model Settings: 
o The model has many settings called hyperparameters. You need to try different values for 
these settings (like the depth of a tree or the learning rate) to find the best combination. 
4. Review the Features: 
o Check which columns (features) the model thinks are important. If the model is relying on a 
bad or messy feature, remove it. 
o Maybe create some new, smarter features from the existing data. 
5. Try Ensemble Methods: 
o Instead of just using one model, train two or three different types of models and combine 
their predictions. This usually makes the overall result more stable and accurate. 
A-3. You are asked to choose an ML algorithm for a new problem. Explain the factors you 
would consider before selecting the algorithm. 
⚙� Key Factors for Choosing an Algorithm 
1. What is the Problem Type? 
o If you are predicting a yes/no answer or a category, you need a Classification algorithm 
(like Logistic Regression). 
o If you are predicting a number (like a price), you need a Regression algorithm (like Linear 
Regression). 
2. How Much Data Do You Have? 
o If you have a small dataset, use simpler models because big, complex models (like deep 
learning) need lots of data to learn properly. 
o If you have very big data, the algorithm needs to be able to run quickly on a lot of 
information. 
3. Does it Need to be Explained? 
o In some fields (like banking), you must explain why the model made a decision. For this, pick 
a simple model (like a Decision Tree). If accuracy is all that matters, you can use a complex 
one. 
4. Speed and Resources: 
o Check how fast the model trains and how fast it gives a prediction in the real world. 
o See if you have the necessary computer power (CPU/GPU) to run the model. 
5. Handling of Features: 
o Some models (like Tree models) are better at handling data that isn't perfectly clean, while 
others (like Neural Networks) need very clean, scaled data. 
A-4. After deployment, an ML model’s performance starts degrading over time. Explain how 
you would identify the cause and what actions you would take. 
�
� Identifying the Cause and Fixing Degradation 
1. Continuous Monitoring: 
o Identify: You need a system that constantly watches the model's performance metrics (like 
accuracy) on the live data. If the metric drops below a certain line, you get an alert. 
2. Check for Data Drift: 
o Identify: Compare the incoming, new data to the original data the model was trained on. If 
the distribution of the features (like customer age or income) has changed, that's Data Drift. 
o Cause: A real-world change (e.g., the economy changed, or a sensor broke). 
3. Check for Concept Drift: 
o Identify: This is when the relationship between the features and the outcome changes. For 
example, a customer who bought product A last year might buy product B this year, even if 
their profile hasn't changed. 
o Cause: The fundamental concept the model learned is no longer true. 
4. Retrain the Model (Action): 
o The main fix is to retrain the model. You take all the new, recent data where performance 
dropped, label it correctly, and train the model again. 
o You should either do this on a schedule (e.g., every month) or when an alert for drift is 
triggered. 
5. Investigate the Source (Action): 
o If it's Data Drift, figure out which part of the data pipeline or the real world changed and fix 
that first. 
A-5. You need to evaluate and compare two machine learning models. Explain how you 
would decide which model is better without using mathematical metrics. 
�
� Non-Metric-Based Model Comparison 
1. Business Value of Errors: 
o Criterion: Which model's mistakes are more acceptable to the company? 
o Example: In a health diagnosis tool, Model A might be slightly less accurate overall, but if it 
never misses a serious disease (low False Negatives), it is the better model, because missing 
a serious disease is the most costly error. 
2. Explainability (Trust): 
o Criterion: Can a user or manager easily understand why the model made its decision? 
o Comparison: If Model A is a simple Decision Tree whose logic is transparent, it will be 
trusted more than a complex Neural Network (Model B), even if Model B is slightly more 
accurate. 
3. Deployment and Operational Cost: 
o Criterion: How much money and effort does it take to run the model 24/7? 
o Comparison: If Model B requires an expensive, high-power GPU server, and Model A runs 
fine on a standard CPU, Model A is the better choice because it is cheaper to operate. 
4. Speed (Latency): 
o Criterion: How fast is the prediction in a live environment? 
o Comparison: For real-time applications, a model that takes 50 milliseconds (Model A) is 
much better than one that takes 500 milliseconds (Model B), regardless of a small difference 
in accuracy. 
5. Robustness (Handling Messy Data): 
o Criterion: Which model handles dirty data (like unexpected text or missing values) better 
without crashing or giving wild answers? 
o Comparison: Models that are more robust in the face of real-world messiness are often 
better for deployment.
