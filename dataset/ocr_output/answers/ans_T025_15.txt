A-5. Explain the role of feature selection and dimensionality reduction. Discuss how these 
techniques help in building efficient ML models. 
Both feature selection (FS) and dimensionality reduction (DR) are critical techniques aimed 
at simplifying the data and combating the Curse of Dimensionality, thereby enhancing the 
efficiency and performance of machine learning models. 
1. Feature Selection (FS) 
 Role: Identifies and selects a subset of the most relevant, non-redundant, and 
informative features from the original feature set, discarding the rest. The original 
feature space is preserved. 
 Methods: 
o Filter Methods: Use statistical measures (e.g., correlation, chi-squared) to 
score features independently of the model. 
o Wrapper Methods: Use a specific ML model to evaluate the performance of 
different feature subsets (e.g., Recursive Feature Elimination). 
o Embedded Methods: Perform feature selection during the model training 
process (e.g., L1 regularization or Lasso). 
2. Dimensionality Reduction (DR) 
 Role: Transforms the data into a lower-dimensional subspace by creating new, 
composite features (projections) that capture the maximum variance of the original 
data. The original feature space is lost. 
 Methods: 
o Principal Component Analysis (PCA): An unsupervised technique that finds 
the directions (principal components) that maximize variance. 
o Linear Discriminant Analysis (LDA): A supervised technique that finds the 
subspace that best separates the different class labels. 
A-6. Describe how machine learning models are deployed and maintained in real-world 
systems. Explain issues such as monitoring, retraining, and performance degradation. 
The process of moving a validated ML model into a live production environment is known 
as Deployment. Maintaining the model's performance over time is the continuous cycle of 
MLOps (Machine Learning Operations). 
Deployment and Serving 
1. Packaging: The trained model, along with its dependencies (libraries, configuration), 
is packaged, often using containerization technologies like Docker. 
2. Deployment: The model is deployed to a serving infrastructure (e.g., a dedicated 
server, cloud service, or edge device) and exposed via a low-latency, scalable REST 
API endpoint. Applications query this API with input data and receive real-time 
predictions. 
3. Testing: Before final release, the new model is often tested against the current 
production model using A/B testing to measure performance impact on actual users. 
Maintenance Issues 
The operational environment is dynamic, leading to critical maintenance challenges: 
1. Performance Degradation (Model Drift): 
o Issue: The model's predictive accuracy inevitably declines over time in 
production. 
o Causes: The primary causes are Data Drift (the statistical properties of the 
input features change, e.g., the average income of customers shifts) or Concept 
Drift (the relationship between the input features and the target variable 
changes, e.g., consumer behavior changes due to a pandemic). 
o Impact: Decreased business value and unreliable predictions. 
2. Monitoring: 
o Role: Continuous, real-time tracking of the model's health and relevance. 
o Metrics Tracked: Data Integrity (monitoring for sudden spikes in missing 
values), Prediction Latency (speed), Data Drift (statistical differences 
between live input and training data), and Model Performance (tracking 
metrics like AUC/F1-Score as ground truth becomes available). 
3. Retraining and Continuous Integration/Continuous Delivery (CI/CD): 
o Role: The process of updating the deployed model with new, more recent data 
to counteract model drift. 
o Triggers: Retraining is triggered either periodically (e.g., every month) or 
event-based (when monitoring detects that data drift or performance 
degradation has crossed a pre-defined threshold). 
o Process: The CI/CD pipeline automates the data ingestion, model training, 
validation, and safe deployment of the new model version, minimizing human 
intervention.

B-1. An e-commerce company wants to reduce product returns. Explain how machine 
learning can be used to analyze customer behavior, product data, and past returns to 
reduce return rates. 
ML Goal: To build a proactive risk management system that predicts the probability of a 
specific customer returning a specific item. 
Data and Modeling 
 Data Sources: Customer history (return frequency, typical return reasons), product 
characteristics (size charts, material, category), user behavior (time spent on page, 
items viewed), and sentiment from product reviews. 
 Model: A Binary Classification model (e.g., Logistic Regression or Gradient 
Boosting Machine) is trained to classify the order as Return (1) or Not Return (0). 
Mechanism for Reducing Return Rates 
1. Risk Score Generation: The model assigns a Probability of Return score to every 
order at the point of checkout. 
2. Targeted Intervention: The platform uses this score to intervene before the product 
ships: 
o Personalized Warnings: If the score is high (e.g., a customer who often returns 
shoes due to size is buying a specific model known to run small), the platform 
displays a pop-up warning: "Based on your return history, customers with your 
profile often size up for this item. Check our recommendation." 
o Fulfillment Hold: Orders with extremely high scores can be flagged for human 
review or held to confirm the order with the customer, verifying the size or 
color choice. 
3. Root Cause Analysis: Analyzing the features that contribute most to the return 
prediction (e.g., inaccurate product description, a specific vendor's poor quality) 
informs the business to make systemic improvements, leading to an overall lower 
return rate.

B-5. A manufacturing company is facing frequent machine breakdowns. Explain how 
predictive maintenance using machine learning can reduce downtime and improve 
operational efficiency. 
ML Goal: To accurately predict the Remaining Useful Life (RUL) of critical machine 
components, enabling maintenance to be performed proactively. 
Data and Modeling 
 Data Sources (IoT/Time Series): Real-time, continuous data streamed from sensors 
on the machines (e.g., vibration magnitude, temperature fluctuations, oil pressure, 
power consumption, acoustics). This is combined with historical maintenance logs and 
failure records. 
 Model: A Regression model (e.g., LSTMs or other time-series models) is trained to 
forecast the RUL or a Classification model is used to predict the probability of failure 
within the next $X$ hours/days. 
Operational Efficiency and Downtime Reduction 
1. Just-in-Time Maintenance: The system moves the company from rigid Preventive 
Maintenance (scheduled, often unnecessary) or costly Reactive Maintenance (after 
breakdown) to Predictive Maintenance. 
2. Optimized Scheduling: Maintenance is scheduled based on the model's prediction, 
ideally during off-hours or before the component reaches a critical threshold. This 
eliminates unexpected, high-cost failures and maximizes machine uptime. 
3. Inventory Management: By knowing when a part will fail, the company can 
optimize its spare parts inventory, ordering components only when the failure 
probability crosses a threshold, saving inventory holding costs. 
4. Prolonged Asset Life: Early detection of small anomalies (like unusual vibration) 
allows for minor fixes that prevent cascading failures and extend the overall lifespan 
of the machinery.
