A-5. Explain the role of feature selection and dimensionality reduction. Discuss how these 
techniques help in building efficient ML models. 
Feature Selection (FS) and Dimensionality Reduction (DR) are two distinct but complementary strategies 
for simplifying the data structure, which is essential for combating the Curse of Dimensionality and 
building high-performance models. 
1. Feature Selection (FS) 
 Role: The process of identifying and retaining a subset of the original, most informative features 
while discarding redundant or irrelevant ones. It maintains the interpretability of the features. 
 Mechanism: Techniques include Filter methods (e.g., correlation coefficient, chi-squared test), 
Wrapper methods (e.g., Recursive Feature Elimination, where the model guides the selection), and 
Embedded methods (e.g., L1 Lasso regularization which performs feature elimination during 
training). 
2. Dimensionality Reduction (DR) 
 Role: Transforming the data into a lower-dimensional subspace by creating new, composite 
features that are linear or non-linear combinations of the original variables. This sacrifices 
interpretability for compression and noise reduction. 
 Mechanism: Principal Component Analysis (PCA) is the primary technique, finding orthogonal 
axes (Principal Components) that capture the maximum variance in the data. 
Contribution to Efficient ML Models 
1. Computational Efficiency: Both FS and DR significantly reduce the number of variables, 
drastically cutting down the computational complexity. This results in faster training times, lower 
memory consumption, and lower prediction latency in production systems. 
2. Improved Generalization (Reduced Overfitting): FS removes noise and redundant features that 
could confuse the model. DR often projects data in a way that minimizes random noise while 
retaining the signal, leading to a more stable model with lower variance. 
3. Enhanced Model Interpretability (FS Focus): A model built on a small, carefully chosen set of 
original features is inherently easier to explain to non-technical stakeholders. 
4. Curse of Dimensionality Mitigation: In high dimensions, data becomes sparse, making distance 
calculations unreliable. Reducing the dimension concentrates the data, making clustering and kernel
based methods more effective. 
A-6. Describe how machine learning models are deployed and maintained in real-world 
systems. Explain issues such as monitoring, retraining, and performance degradation. 
The deployment and maintenance of machine learning models is managed under the discipline of MLOps 
(Machine Learning Operations), which governs the entire lifecycle from development to production. 
Deployment and Model Serving 
1. Packaging and Containerization: The trained model, along with its configuration, dependencies, 
and inference code, is packaged, typically using frameworks like Docker, to ensure environmental 
consistency across development and production. 
2. Model Serving: The packaged model is hosted on a scalable infrastructure and exposed as a low
latency service, often a REST API endpoint. This allows client applications to send input data and 
receive real-time predictions. 
3. Canary and A/B Testing: Before a new model fully replaces the old one, it is often tested on a 
small fraction of live traffic (Canary release) or run alongside the old model (A/B testing) to validate 
its performance and stability. 
Maintenance and Lifecycle Issues 
1. Performance Degradation (Model Drift): 
o Issue: The model’s accuracy and predictive power decline over time as the real-world 
environment changes. 
o Causes: Data Drift (changes in the input data distribution, e.g., customer demographics 
shifting) or Concept Drift (changes in the fundamental relationship between inputs and 
outputs, e.g., fraudsters adopting new attack patterns). 
2. Monitoring: 
o Role: Continuous, automated tracking of the model’s performance and health in production. 
o Metrics Tracked: Data Quality/Integrity (missing values, feature range violations), Model 
Performance (latency, throughput), Drift Metrics (statistical distance between production 
data and training data). 
3. Retraining: 
o Role: The process of updating the model by training it on fresh, recent data to counteract 
model drift. 
o Triggers: Retraining is typically triggered either periodically (e.g., every quarter) or event
based (when monitoring detects that the model's performance or data drift metrics exceed a 
predefined threshold). This ensures the model's rules remain relevant to current reality.

B-1. An e-commerce company wants to reduce product returns. Explain how machine 
learning can be used to analyze customer behavior, product data, and past returns to 
reduce return rates. 
ML Goal: To implement a proactive intervention system by predicting the probability of an order resulting 
in a return before it is shipped. 
Data Aggregation and Modeling 
 Data Sources: Deep customer history (return frequency, typical return categories, preferred sizes), 
granular product data (sizing consistency, material elasticity), user behavior (time spent comparing 
sizes), and aggregated customer review sentiment. 
 Model: A Binary Classification Model (e.g., XGBoost, Logistic Regression) trained on order-level 
data, with the target variable being 'Returned' or 'Not Returned'. 
Mechanism for Reducing Return Rates 
1. Risk Scoring: The model generates a Return Risk Score for every item in the cart. The score is 
highly influenced by mismatched features (e.g., a customer who typically returns large-sized shirts 
is buying a shirt from a brand known to run small). 
2. Targeted Intervention: If the score exceeds a threshold, the platform deploys a personalized 
intervention at checkout: 
o Proactive Warning: Displaying a message like, "Our data suggests this item runs small 
compared to your usual purchases. We recommend sizing up." 
o Fulfillment Flag: For extremely high-risk orders, the warehouse can be flagged to perform 
an additional quality check or size verification. 
3. Business Intelligence: Analyzing the most predictive features (e.g., a specific vendor's inconsistent 
sizing contributes $30\%$ of the risk) informs business decisions to improve quality control and 
reduce returns at the source. 
B-2. A bank wants to detect fraudulent transactions in real time. Describe how machine 
learning can be applied for fraud detection, including data sources, model behavior, and 
challenges involved. 
ML Goal: To provide a low-latency, highly accurate risk assessment for every transaction to decide on 
approval, denial, or flagging for review. 
Data Sources and Model Behavior 
 Data Sources: Transaction metadata (amount, merchant, country code), aggregated account history 
(average spend, velocity features like # transactions in the last hour), and sophisticated behavioral 
features (e.g., geolocation changes, device ID consistency). 
 Model: A combination of Supervised Classification (trained on labeled fraud data) and 
Unsupervised Anomaly Detection (e.g., Isolation Forest, Autoencoders) to identify novel attack 
vectors. 
 Real-Time Requirement: Models must be engineered for extreme low latency (under $50$ ms), 
typically deployed as optimized microservices. The output is a Fraud Risk Probability. 
Challenges Involved 
1. Extreme Class Imbalance: Fraud rates are often $<0.1\%$. The model must be evaluated using 
metrics like AUC-PR (Precision-Recall), and trained using techniques like SMOTE or cost-sensitive 
learning. 
2. Adversarial Concept Drift: Fraudsters actively modify their methods to bypass current detection 
rules, leading to constant and rapid decay of the model's efficacy, necessitating continuous 
retraining. 
3. Cost Asymmetry: The cost of a False Negative (missing fraud) is the full amount of the transaction, 
while a False Positive (wrongfully declining a legitimate purchase) leads to customer dissatisfaction 
and lost revenue. Models must be tuned to prioritize high Precision. 
B-3. A hospital plans to predict patient readmission rates. Explain how machine learning can 
support this task, from data collection to using predictions for better healthcare decisions. 
ML Goal: To accurately identify patients at the highest risk of readmission within a short timeframe (e.g., 
30 days) after discharge, enabling timely clinical intervention. 
Data Collection and Modeling 
 Data Sources: Comprehensive data from Electronic Health Records (EHR) covering: Clinical 
Factors (primary and secondary diagnoses via ICD codes, lab results), Utilization History (number 
of prior admissions, length of stay), and Socio-Behavioral Factors (medication adherence history, 
social support documented by case workers). 
 Model: A Binary Classification Model (often using gradient boosting or deep learning on tabular 
data) trained to predict $P(\text{Readmission} | \text{Patient Profile})$. 
Using Predictions for Better Healthcare Decisions 
1. Risk Stratification: The model generates a risk score for all patients at the time of discharge, 
stratifying them into high, medium, and low-risk groups. 
2. Personalized Intervention: High-risk patients are immediately enrolled in specialized, high
intensity Transition of Care programs: 
o Daily telephonic follow-up by a nurse to verify medication adherence. 
o Scheduling home-health visits by social workers. 
o Prioritizing complex case management. 
3. Resource Optimization: The model shifts the hospital from a blanket approach to care management 
to a targeted approach, ensuring that expensive human resources are deployed only to the patient 
cohort where they can have the maximum impact on reducing preventable readmissions. 
B-4. A social media platform wants to control the spread of fake news. Discuss how machine 
learning can help identify and limit misinformation while considering ethical challenges. 
ML Goal: To swiftly identify, score, and limit the visibility of deliberately misleading or harmful content 
while upholding the principles of free expression. 
ML Identification and Limitation 
1. Content and Source Analysis (NLP): Models analyze textual content for features associated with 
misinformation: sensationalism, emotional language, lack of verifiable source links. They also 
analyze the source's publishing history and credibility score. 
2. Propagation Analysis (Graph ML): Advanced algorithms (e.g., Graph Neural Networks) 
examine the spreading patterns. Coordinated, non-organic virality (sudden spikes in shares/likes) or 
propagation via known bot networks are high-risk indicators. 
3. Action: High-risk content is subjected to demotion (algorithmic throttling of visibility in feeds) or 
supplemented with fact-check overlays, providing transparent context to the user. 
Ethical Challenges 
1. Censorship and Bias: The core challenge is balancing platform integrity with free speech. If the 
model's training data reflects a specific political or social bias, the model will disproportionately 
suppress legitimate viewpoints, leading to accusations of algorithmic censorship. 
2. Transparency and Explainability: Due to the complexity of deep learning models, explaining why 
a post was flagged is difficult. Lack of clarity erodes user trust and prevents effective appeals. 
3. Adversarial Defense: Misinformation creators constantly test new encoding methods (using images, 
misspellings, or unique phrasing) to bypass the models, creating a persistent, costly arms race known 
as model evasion. 
B-6. An online education platform wants to personalize learning for students. Describe how 
machine learning can be used to recommend content, track performance, and improve 
learning outcomes. 
ML Goal: To create a truly adaptive learning system that customizes the curriculum path, pace, and 
remediation strategy for every individual learner. 
Content Recommendation (Adaptive Learning) 
1. Mastery Modeling: Advanced models (e.g., Knowledge Tracing models) continuously assess a 
student's latent knowledge state for every granular concept, rather than just quiz scores. 
2. Personalized Pathing: Using techniques like Reinforcement Learning or recommender systems, 
the platform selects the next piece of content that maximizes the student's learning gain while 
maintaining engagement (not too hard, not too easy). 
3. Remediation and Scaffolding: If a student struggles, the model identifies the specific prerequisite 
concept that is missing and serves targeted remedial material before reintroducing the failed concept, 
optimizing the learning loop. 
Performance Tracking and Outcome Improvement 
1. Early Warning System: Models monitor fine-grained behavioral features (time spent on tasks, 
number of attempts, consistency of practice) to predict the probability of course dropout or failure 
with high accuracy. 
2. Targeted Intervention: When a student is flagged as high-risk, the platform can deploy automated 
motivational messages or alert a human tutor, enabling proactive support. 
3. Optimized Learning: By ensuring the student's time is spent solely on material relevant to their 
current learning gaps, the ML system minimizes wasted effort, drastically increasing engagement 
and maximizing the overall course completion and success rates.
