A-1. You are given a dataset with missing and inconsistent values. Explain the steps you 
would follow to clean and prepare the data for a machine learning model. 
�
� Steps for Data Cleaning and Preparation (Focus on Deep Learning and Robustness) 
1. Noise Robustness via Denoising Autoencoders: 
o Action: For high-dimensional or image-like data, train a Denoising Autoencoder (DAE). 
The DAE learns a compact representation of the data and can reconstruct corrupted inputs, 
effectively imputing missing patches or filtering noise by learning the underlying data 
manifold. 
o Goal: Provides a highly non-linear, robust form of imputation and dimensionality reduction, 
especially effective for deep models. 
2. Imputation using Structural Equation Modeling (SEM): 
o Strategy: Model the direct and indirect causal effects between variables. Use SEM to 
estimate missing data points based on a validated theoretical model of how the features 
interact, rather than purely statistical correlation. 
o Benefit: Ensures that the imputed values are justifiable by established domain theory, leading 
to a more reliable trained model. 
3. Handling Categorical Feature Interactions: 
o Action: Implement techniques to capture interactions between categorical features that 
simple encoding misses. Use Factorization Machines (FMs) or Field-aware Factorization 
Machines (FFMs) to learn weight parameters for second-order feature interactions. 
o Goal: Generate interaction features implicitly, which is highly valuable in recommendation 
systems and click-through rate prediction. 
4. Data Partitioning for Time Series (Backtesting): 
o Action: For time-dependent data, use Walk-Forward Cross-Validation. Instead of static 
splits, the model is sequentially trained on an expanding window of historical data, then 
tested on the next future period. 
o Goal: Provides a far more realistic evaluation of the model's predictive utility in a production 
environment where time is directional. 
5. Final Feature Selection using Recursive Feature Elimination (RFE): 
o Action: Employ RFE with the final chosen algorithm. The model is repeatedly trained, and 
the least important features are pruned based on coefficient size or feature importance scores 
until the optimal feature subset is found. 
o Goal: Creates a highly parsimonious model that is less prone to variance. 
A-2. A trained ML model is giving inaccurate predictions on new data. Describe the steps you 
would take to analyze and improve the model’s performance. 
�
� Steps to Analyze and Improve Performance (Focus on Adversarial Robustness and Data 
Augmentation) 
1. Analysis of Adversarial Vulnerability: 
o Diagnosis: Test the trained model against small, intentionally crafted perturbations (e.g., 
Fast Gradient Sign Method - FGSM) on the new data that are imperceptible to humans but 
cause misclassification. 
o Action: If the model is highly vulnerable, implement Adversarial Training during retraining 
by including these perturbed examples in the training loop. This improves robustness against 
minor, real-world noise. 
2. Hypothesis Testing for Concept Drift: 
o Diagnosis: Formulate specific hypotheses about why the model's underlying rules might have 
changed (e.g., "The effect of Feature X has decreased since the policy change"). 
o Action: Use A/B testing or observational data analysis to validate these hypotheses, guiding 
targeted feature updates instead of blind retraining. 
3. Data Augmentation for Coverage Gaps: 
o Action: If the inaccuracy is concentrated in areas where the new data differs from the 
training data, use Synthetic Minority Over-sampling Technique (SMOTE) or related 
generative methods (like GANs) to synthesize new training samples in the underrepresented 
regions of the feature space. 
o Goal: Address data scarcity and improve the model's coverage of challenging boundary 
cases. 
4. Residual Error Modeling: 
o Action: Train a second, simpler machine learning model (e.g., a Linear Regressor) whose 
target variable is the residual error of the primary model on the new data. 
o Goal: Identify systematic, uncaptured biases in the primary model that can be used for 
explicit error correction or to inform the next version's architecture. 
5. Bias Correction using Post-Hoc Calibration: 
o Action: If the model shows consistent bias (e.g., constantly overpredicting in regression or 
underpredicting the minority class), apply post-hoc bias correction algorithms (e.g., using a 
temperature parameter in a Neural Network's softmax layer) to align prediction distribution 
with observed reality. 
A-4. After deployment, an ML model’s performance starts degrading over time. Explain how 
you would identify the cause and what actions you would take. 
Identification and Corrective Actions (Focus on Systemic Drift and Economic Retraining) 
1. Monitor Feature Importance Divergence: 
o Identification: Track the distance between the feature importance vector in training and the 
current feature importance vector in production using measures like Cosine Similarity. 
o Goal: Quickly identifies if the model is structurally changing its interpretation of the data, 
which may precede measurable performance drop. 
2. Monitor for Feedback Loop Contamination: 
o Identification: Check if the model's own predictions are being fed back into the data used for 
subsequent scoring or retraining. 
o Cause: Feedback Loop Contamination can lead to self-fulfilling prophecy errors and 
catastrophic model collapse. 
o Action: Implement a shadow logging strategy where the predictions used for retraining are 
strictly separated from the input features. 
3. Dynamic Retraining Cost Analysis: 
o Action: Don't just trigger retraining when performance drops. Use an economic model: 
Retrain only when Cost of Degradation (loss from inaccurate predictions) > Cost of 
Retraining (compute and engineering time). 
o Goal: Optimize the MLOps process for profit maximization, not just statistical accuracy. 
4. Causal Feature vs. Correlational Feature Tracking: 
o Identification: Separate monitored features into two groups: those known to be causal and 
those that are merely correlational. 
o Action: Degradation due to a shift in correlational features is normal and often requires 
retraining. Degradation due to a shift in causal features is a sign of a fundamental, system
level change that requires domain investigation. 
5. Rollback via Canary Deployment: 
o Action: When deploying a new model version (or a retrained version), use Canary 
Deployment, where the new model only serves a tiny fraction (e.g., 1%) of the traffic. 
o Mitigation: If the performance of the canary model is worse than the current model, the 
system immediately rolls back to the stable version, isolating the degradation. 
A-5. You need to evaluate and compare two machine learning models. Explain how you 
would decide which model is better without using mathematical metrics. 
Non-Metric-Based Model Comparison (Focus on System Risk and Organizational Fit) 
1. Data Governance and Privacy Risk: 
o Criterion: Which model's architecture or required feature set poses a lower risk of exposing 
sensitive or PII (Personally Identifiable Information)? 
o Comparison: Model A, which can achieve comparable results using synthetic data or 
federated learning (keeping data localized), is better than Model B, which requires 
centralized PII, reducing regulatory and reputational risk. 
2. System Latency Reliability (P99 Jitter): 
o Criterion: Instead of average latency, compare the P99 latency (the time the slowest 1% of 
predictions take). 
o Comparison: Model A, which maintains a low P99 latency (consistent speed for all users), is 
operationally more reliable than Model B, which has a faster average but massive P99 spikes, 
leading to system timeouts and poor user experience for a small, critical subset of users. 
3. Model Resilience to Missing Features: 
o Criterion: If a necessary feature is temporarily unavailable due to an upstream failure, how 
gracefully does the model degrade? 
o Comparison: Choose the model (Model B) that has a built-in fallback strategy (e.g., using 
simpler features or default values) and continues to provide a reasonable, albeit less accurate, 
prediction, over Model A, which throws an error and crashes the service. 
4. Organizational Knowledge Transfer and Onboarding Cost: 
o Criterion: How easily can a new machine learning engineer be onboarded and understand 
the model's code, structure, and dependencies? 
o Comparison: Model B, which uses standard, common techniques (e.g., XGBoost, standard 
PyTorch layers), is better than Model A, which uses exotic, cutting-edge research algorithms, 
as Model B reduces organizational friction and long-term hiring costs. 
5. Deployment Artifact Size and Bandwidth: 
o Criterion: The physical size (megabytes) of the serialized model file (the deployment 
artifact). 
o Comparison: A smaller model file (Model A) is always better, as it reduces storage costs, 
improves deployment speed, and minimizes bandwidth consumption during over-the-air 
updates for edge or mobile devices.
