A-3. Describe the function of an embedding in machine learning. Why are embeddings useful for text, 
images, or categorical data? 
Answer 
Definition & purpose: 
An embedding is a learned dense vector representation that maps discrete, sparse, or high-dimensional 
inputs into a continuous low-dimensional space where semantic or functional similarity is preserved by 
geometric proximity. 
Function (mechanics & benefits): 
 Dimensionality reduction: Replace extremely high-dimensional spaces (one-hot encodings, raw 
token indices, raw pixels) with compact vectors that are much easier for models to process. 
Usefulness by modality (concrete): 
 Images: CNN-produced embeddings encode shapes, textures, and object presence; useful for image 
retrieval, few-shot learning, and as inputs for downstream classifiers. 
 Categorical features: Learned category embeddings (e.g., for product IDs, user IDs) allow the 
model to learn latent relationships between categories instead of relying on sparse one-hot vectors; 
this is especially powerful in recommendation systems and tabular models. 
Practical considerations: 
 Choose embedding dimensionality to balance representational capacity vs overfitting. 
 Pretraining on large corpora or using contrastive objectives often yields robust embeddings. 
 Fine-tune embeddings for downstream tasks when labeled data is available for better task alignment. 
A-4. What is concept learning in ML? Explain how hypothesis space and inductive bias influence concept 
learning. 
Answer 
Definition: 
Concept learning is the process of inferring a general rule or classifier (a concept) from specific labeled 
examples. The goal is to produce a hypothesis that correctly classifies unseen instances. 
Hypothesis space (H): 
 What it is: The set of all candidate hypotheses or functions the learner can possibly select (e.g., all 
linear functions, depth-limited decision trees, neural networks of a certain architecture). 
 Role: It bounds what the learning algorithm can represent. If the true target concept is not in H, no 
amount of data will let the learner represent it perfectly (representational bias). 
 Trade-offs: A larger H increases expressive power but raises the risk of overfitting and makes 
search harder. 
Inductive bias: 
 Definition: The set of assumptions that the learning algorithm uses to choose one hypothesis over 
another when multiple hypotheses are consistent with the training data. Examples include preferring 
simpler hypotheses (Occam’s razor), linearity assumptions, or smoothness constraints. 
 Necessity: With finite data, inductive bias is essential; without bias, any hypothesis consistent with 
training data is equally plausible and generalization is impossible. 
How they influence concept learning: 
 Learnability: The intersection of H and the inductive bias determines whether the learner can 
generalize from samples to unseen examples. A well-chosen hypothesis space aligned with the 
problem and an appropriate inductive bias leads to better generalization. 
 Search & efficiency: Inductive bias guides the search through H (e.g., greedy splits in decision trees 
vs gradient descent in neural nets), improving learning efficiency. 
 Error decomposition: Inductive bias contributes to bias-variance trade-off — strong bias reduces 
variance but may incur systematic error if incorrect; weak bias can fit complex functions but risks 
high variance. 
 Practical example: If H is linear functions and the true concept is nonlinear, the learner will 
underfit. If H is very flexible (deep nets) but inductive bias (regularization, architecture choices) is 
inadequate, the learner may overfit. 
Conclusion: Designing H and inductive bias thoughtfully (via model family, regularization, feature 
transforms) is central to successful concept learning. 
A-6. What is active learning? Describe how query strategies like uncertainty sampling help improve 
training efficiency. 
Answer 
Definition & goal: 
Active learning is a paradigm where the learning algorithm chooses which unlabeled instances it wants 
labeled (by an oracle, typically a human annotator) to maximize model performance for the least labeling 
cost. The goal is to achieve target accuracy with far fewer labeled examples than passive learning. 
Core idea & workflow: 
1. Train an initial model on a small labeled seed set. 
2. Score the unlabeled pool with an acquisition function (uncertainty, disagreement, expected error 
reduction, etc.). 
3. Select top-k most informative samples, obtain labels from annotators. 
4. Retrain/fine-tune the model and repeat the cycle. 
Query strategies (explanations & examples): 
 Uncertainty sampling: Choose instances where the model is least confident — e.g., lowest 
maximum predicted probability, smallest margin between top two class probabilities, or highest 
predictive entropy. These examples typically lie near decision boundaries and, when labeled, provide 
maximal information to refine boundaries. 
 Query-by-committee: Maintain an ensemble (committee) of diverse models and select instances 
with maximal disagreement among committee members. This targets epistemic uncertainty due to 
model uncertainty. 
 Expected model change / Expected error reduction: Compute which candidate labels would most 
change parameters or reduce expected generalization error; select samples that maximize this 
objective. 
 Diversity-based sampling: Combine uncertainty with explicit diversity constraints to avoid 
selecting many near-duplicate instances and to cover broad regions of the input space. 
Benefits & practical notes: 
 Substantially reduces labeling effort in domains where annotation is expensive (medical images, 
expert transcription). 
 Works best when the unlabeled pool is large and annotation throughput is limited. 
 Practical deployment requires handling label noise, human annotator variability, and correct 
calibration of acquisition functions. 
 Combining uncertainty with diversity and using batch-mode active learning (selecting batches of 
diverse uncertain examples) is common in practice.

B-2. Assume you have trained a classification model that shows high accuracy but low recall. Explain the 
activities you would perform to diagnose and improve this issue. 
Answer 
Diagnosis: 
 Confusion matrix: Confirm that false negatives are high. 
 Class distribution: Check whether the positive (target) class is under-represented causing class 
imbalance. 
 Probability calibration: Inspect predicted probabilities; many true positives may be predicted with 
low probability below threshold. 
 Feature signal: Examine whether features discriminate the positive class; use feature importance or 
SHAP to find missing signals. 
Improvement activities (ordered): 
1. Threshold tuning: Plot precision-recall curve and choose a threshold that raises recall to acceptable 
level while controlling precision loss. 
2. Resampling / weighting: Apply oversampling (SMOTE) or class weights in the loss function or 
focal loss to emphasize minority class. 
3. Model choice & tuning: Try models that better capture minority patterns (tree ensembles, gradient 
boosting, tuned neural nets) and tune hyperparameters with a recall-focused objective. 
4. Feature engineering: Create new features or transformations that highlight minority-class 
characteristics (interaction terms, ratio features, temporal aggregations). 
5. Ensembling & stacking: Combine complementary models to reduce blind spots and improve recall. 
6. Calibration & post-processing: Calibrate probabilities (Platt scaling, isotonic) and adjust thresholds 
per subpopulation if necessary. 
Validation: 
 Use stratified cross-validation and monitor precision-recall curves and AUPRC rather than accuracy. 
Evaluate downstream costs of false negatives vs false positives to choose operating point. 
B-4. You receive a trained model whose predictions are biased toward a specific class. Describe the 
activities you would conduct to detect, measure, and reduce bias. 
Answer 
Detection: 
 Distribution checks: Compare predicted label distribution with actual distribution across the entire 
dataset and across demographic subgroups. 
 Confusion matrices by subgroup: Produce confusion matrices segmented by protected attributes 
(e.g., gender, region) to observe discrepancies. 
 Error decomposition: Identify whether bias arises from data imbalance, label noise, or feature 
proxies. 
Measurement (fairness metrics): 
 Demographic parity difference: Difference in positive prediction rates across groups. 
 Equal opportunity (TPR parity): Compare true positive rates across groups. 
 False positive/negative rate gaps: Check FPR/FNR differences to detect disparate harms. 
 Disparate impact ratio: Ratio of favorable outcomes between groups. 
Mitigation strategies: 
 Pre-processing: Rebalance training data (oversample underrepresented groups), remove or 
transform proxy features correlated with protected attributes, and generate synthetic examples if 
feasible. 
 In-processing: Use fairness-aware learning algorithms (constrained optimization to satisfy parity 
constraints), or incorporate regularizers that penalize disparity. Adjust class weights to counteract 
imbalance. 
 Post-processing: Calibrate scores and set group-specific thresholds to equalize selected fairness 
metrics (with careful ethical review). 
 Human-in-the-loop: Review failure modes and consult stakeholders to define acceptable trade-offs 
between fairness and other metrics. 
Validation & governance: 
 Use a separate fairness test set, track fairness metrics over time, and implement alerting for drift in 
disparity measures. Document mitigation choices and rationale for auditability. 
B-5. During deployment, your ML model starts performing poorly after a few months. Explain the 
activities you would carry out to monitor, identify, and fix model drift. 
Answer 
Monitoring (continuous): 
 Instrument dashboards to track model performance metrics (accuracy, precision, recall, AUC), input
feature distributions, prediction confidence, and calibration over time. Log metadata (time, input 
versions) to enable diagnostics. 
Detection & identification: 
 Use statistical drift detectors (Population Stability Index, KS test, JS divergence) for feature 
distributions and monitor changes in prediction distributions. Periodically sample recent predictions 
for labeling to measure true performance. Correlate performance drops with external events 
(seasonality, policy changes) or upstream data-pipeline changes. 
Root-cause analysis: 
 Identify which features changed significantly and whether label-generating processes have shifted. 
Check for data-quality issues (schema drift, missing features, corrupted pipelines). Use 
counterfactual or SHAP-based analysis to see which features contribute to degraded predictions. 
Fix strategies: 
 Quick fixes: Recalibrate model probabilities or adjust decision thresholds if calibration shifted. 
Implement fallback rules for critical decisions. 
 Retraining: Collect recent labeled data and retrain or fine-tune the model using a combination of 
historical and recent examples; consider temporal cross-validation (time-based splits). 
 Incremental updates / online learning: If appropriate, apply incremental learning methods to adapt 
continuously while controlling catastrophic forgetting. 
 Feature engineering: Replace deprecated features, add new signals that capture new behavior, or 
remove noisy features. 
 Model architecture changes: If relationship structure changed, consider switching to a more 
appropriate model family. 
Validation & rollout: 
 Validate updated models on temporally realistic holdout sets and run canary or A/B tests before full 
deployment. Maintain rollback capability and continue monitoring post-deployment. 
Operationalize: 
 Automate drift detection, periodic retraining pipelines, and maintain labeled holdout sets for 
continuous evaluation.
